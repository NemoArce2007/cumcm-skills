# LOOP.md — 每个技能内部怎么停

Loop engineering：你设计循环，而不是手写下一句 prompt。模型自己跑 `discover → plan → execute → verify`，直到 **verifier 变绿** 或触及上限。

本仓库每个 skill 都是一个带 verifier 的节点。`contest-run` 只决定节点之间怎么走，不代替节点内部的循环。

## 标准循环

```
discover  读 contest-state.json + 本节点需要的输入文件
plan      列出本轮要改的最小集合（禁止一次重写全文）
execute   只做计划内的事，并写回状态
verify    跑本 skill「验收」一节的每一条
          全绿 → 停，写 status
          有红 → 把失败项写入 gate_failures，下一轮只修红项
```

## 必须写清的四件事

每个 `SKILL.md` 的「循环」一节必须有：

| 字段 | 规则 |
| --- | --- |
| 目标 | 一句话，可判定完成 |
| 验收 | 条目化；每条是观察，不是形容词（禁止“较好”“合理”单独作为通过条件） |
| 停止 | 全绿，或达到 `max_rounds`（默认 4）后输出未通过清单并停 |
| 失败路由 | 红项对应回到哪个节点（通常是自己；跨节点失败由 Graph 规定） |

## 验收写法

- 通过：`摘要专用页不超过 1 页`（可打开 PDF 看）
- 不通过：`摘要写得好`（无法自动判定）
- 通过：`每个小问都有 baseline 与 primary 两个模型名`
- 不通过：`模型有创新`

## 禁止

- 验收失败仍把 `status` 向前推进
- 用“再让 AI 润色一遍”代替修红项
- 为了过验收编造数据、文献、运行结果
- 把检测工具的“AI 率”当停止条件

## 人在环上的位置

人只进入慢循环：选题、是否采纳高风险假设、是否把某段作为核心建模。节点内的快循环由 Agent 自己跑完，再把 `gate_failures` 给人看。
